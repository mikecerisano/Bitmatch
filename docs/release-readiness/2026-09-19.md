# Finishing the next BitMatch release

Audit of source revision `3debabe` on 2026-09-19. Three Luna agents reviewed transfer integrity, recovery/reporting, and cross-platform experience; the orchestrator reviewed release status and checked the findings. This is a source audit, not a fresh test run. The last recorded suite passed 484 tests on September 8.

## Release scope

A simple, dependable card offloader on Mac, iPhone, and iPad: select source and backups, verify the copies, explain problems, recover safely, and export trustworthy evidence. Avoid adding unrelated features before these workflows are complete.

## Integrity fixes first

- **Cancellation must remain cancelled.** Folder comparison checks its cancellation flag between files, but not after the final checksum operation. A cancellation during that last operation can return normal statistics and publish completion (`ComparisonCoordinator.swift`, `SharedAppCoordinator.swift`). Check cancellation before publishing and propagate it into long-running comparison work. This is a source-confirmed control-flow gap; the large-file reproduction still needs a regression test.
- **Align preflight with the copy manifest.** `SafetyValidator.validateSourceTreeForCopy` traverses root volume metadata that `FileTreeEnumerator` intentionally skips. Apply the same root-only policy to both. Permission and portable-path failures inside excluded metadata are a potential failure path, not a demonstrated cause of issue #8; reproduce with fixtures before claiming a fix for that report.

## Priorities

1. **Make comparison problems actionable.** The comparator calculates filename sets but returns counts only (`Shared/Core/Services/ComparisonCoordinator.swift`, `CompareStats` in `SharedAppCoordinator.swift`). Retain and display missing, extra, and mismatched paths, with export. GitHub issue [#8](https://github.com/mikecerisano/Bitmatch/issues/8) reports one destination-only item from a Sony Venice offload in v0.1.4. Its cause is not established: the report provides no filename. Reproduce generated-metadata and camera-card cases without hiding unexpected media.
2. **Unify completion exports with retained evidence.** Mobile completion calls `ReportCoordinator`, which builds a summary from folder information instead of authoritative per-file results, ASC issues, and project provenance. It opens a temporary PDF through generic URL opening and ignores the returned success flag. Use the same complete record as history and expose a real save/share flow with visible errors.
3. **Make recovery possible after access expires.** `LocalTransferResource.resolve` rejects stale bookmarks; Retry resolves the same immutable locations. Provide a reauthorization/reselection flow that validates the original volume and folder identity, preserves earlier attempts, and never silently substitutes another drive.
4. **Include report failures in the final outcome.** Automatic report export catches save errors and returns no structured outcome to the executor. Distinguish verified media from a failed requested report, retain that issue in history, and stop a queue that needs attention.
5. **Complete remote queue scheduling.** Mac queues newly requested off-site items, but persisted work is not scheduled on startup. Transient failures record a future `nextAttemptAt` without a worker to run again (`BitMatch/App/AppCoordinator.swift`, `Shared/Core/Services/RemoteBackupQueue.swift`). Restore and schedule eligible work, with bounded retries and visible retry/cancel controls.
6. **Finish the intended ASC handoff scope.** Initial inventories pass recorded official reference checks; inherited histories are deliberately unsupported. Choose and document the supported professional handoff workflow, validate it with representative real media and receiving tools, and keep local-copy verification separate from handoff status. Do not claim full chain-of-custody support yet.
7. **Validate physical storage and ship the binary.** The hardware register has no physical-device results. Exercise real cards/readers, APFS/exFAT, disconnect/reconnect, full destinations, and iOS interruption/relaunch. Then run local release gates, bump the version, sign/notarize, and publish the new download. Current public release remains v0.1.4 from September 3; newer work is source-only. GitHub Actions stays disabled at the user's request.

## Acceptance bar

- Every failed or partial operation explains what happened and offers a valid next action.
- Quick copies never appear checksum-verified.
- Report/history exports preserve all results and handoff issues.
- Relaunch and retry preserve original attempts and confirm original storage identities.
- Mac, iPhone, and narrow iPad support the same essential workflow with touch-accessible actions.
- Passing automated tests, physical test results, and untested combinations are reported separately.

## Smaller interface fixes

The mobile project setup buttons and field label contain four missing Swift string interpolations (`BitMatch-iPad/Views/CopyAndVerifyView.swift`, lines 409, 414, 416, and 434), exposing literal implementation text. Fix these and inspect the actual project-transfer flow on phone and tablet.

Cancelled transfers are retryable but omitted from the Queue filter. Make their recovery action discoverable without requiring users to find History.

Mobile destination cards label every selected folder “External Drive,” even for local folders. Use the actual storage type when available or neutral folder wording. Give the phone and tablet gear buttons an explicit Settings accessibility label. Keep the foreground-only transfer limitation visible; the background task registration is not an unattended transfer implementation.

## What already looks strong

The local copy service uses pinned directory descriptors, rejects symlink traversal, writes exclusive temporary files, and publishes without overwriting existing files. ASC generation checks destination bytes and file stability before atomic publication. Preserve these safeguards while completing the recovery and presentation paths. This audit is not a guarantee of correctness or a substitute for the physical-storage validation above.
